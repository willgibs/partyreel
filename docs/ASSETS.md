# The asset log

> **ROLE:** the assets Will has open for the site, requested or parked, one row each, so nothing asked for is lost.
> **BELONGS HERE:** what, the exact spec, the slot it lands in (the stand-in it replaces, by id) and its status.
> **NOT HERE:** why a design needs it (the board says that), the wiring (the wiring round's commit), a delivered, wired
> or withdrawn row (git keeps it). **GROWS BY:** the Orchestrator adds each manifest's asset asks at integration under
> the next free number; Will marks a row `delivered`; the wiring round swaps it in by id and deletes the row. A number
> is never reused: code and boards cite rows by number.

**How to deliver.** Drop the files in the inbox outside the repo, `/Users/gibby/local/ai/partyreel-assets/<row>/`
(delivered media is large and unoptimised; only what a wiring round ships enters `public/marketing/`, sized and named
by `marketing-media.ts`), then mark the row `delivered` here or say so in chat; the Orchestrator commits the log.
Will's edits to this file are safe beside the Orchestrator's (it stages explicitly and reads the file before every
edit); an agent never edits it and asks in its manifest's Handoff instead, one bullet per asset.

**Status:** `requested` → `delivered` → wired (the row leaves); `parked` while the asset waits on a pick or a queued
idea (the reason rides the status).

**The source:** one Higgsfield month generates every image and every video on the site ([`ROADMAP.md`](ROADMAP.md),
"Generated media" under Before launch). Nothing is shot or licensed, and no row tracks where an image came from: an
image we use is one we hold the rights to. **An ask names the slot, never the picture:** where the frame sits, its
size and aspect, the crops it must survive and where type lands on it. The agent that runs the month researches
Higgsfield's tooling first and writes every final prompt itself, so a row's creative detail is context for it, not a
prompt.
