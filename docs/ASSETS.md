# The asset log

> **ROLE:** Will's running list of every asset a round has requested, so he can produce them in
> parallel to reviews and tasks and nothing asked for is lost. **BELONGS HERE:** one row per asset:
> what, the exact spec, who asked (the track), the stand-in it replaces by id, where it stands, and
> where the file is once it exists. **NOT HERE:** why a design needs it (the manifest and the board
> say that), or the wiring itself (the wiring round's commit). **GROWS BY:** the Orchestrator folds
> each manifest's "Assets requested from Will" line at integration; Will marks a row `delivered` and
> fills `where`; the wiring round marks it `wired` and deletes the stand-in. Rows are never deleted;
> a wired row is the record of what replaced what.

**How to deliver.** Drop the files in the inbox outside the repo,
`/Users/gibby/local/ai/partyreel-assets/<row>/` (delivered media is large and unoptimised; only what
a wiring round ships enters `public/marketing/`, sized and named by `marketing-media.ts`), then mark
the row `delivered` here or say so in chat. Either way the Orchestrator commits the log. Will's edits
to this file are safe beside the Orchestrator's (it stages explicitly and reads the file before every
edit); no agent edits it (asks go in the manifest's Handoff, one bullet per asset).

**Status:** `requested` → `delivered` → `wired`; `parked` when the round that asked was not ruled in but
the asset still serves a queued idea; `withdrawn` when nothing uses it (the row stays as the record).
