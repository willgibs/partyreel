# Ideas worth keeping (from the fifth batch's reviews, 2026-09-20)

Not rulings, not lane briefs: the ideas two fresh-context reviews and I produced tonight that no board holds yet.
Each is one paragraph; the ones a board should ask move to `atlas/gaps.md` when they earn a seat.

- **The QR as the event's live door.** The header code on the hub is a real, scannable code whose state is the
  event's state: uploads paused dims it, a private event marks it. A host at the door holds the phone up and the
  mini-modal IS the door. If this reads well on the alias it becomes the pattern for every place a code appears.
- **The next best step, not a queue.** A dashboard that shows "what needs you" must never be empty; the honest
  filler is one suggested job per event computed from real state (a queue, paused uploads, a live event with no reel,
  a code to print for tomorrow, storage near the cap). This is a pure function; it should live once and feed the
  pulse, the event card and maybe an email.
- **Overtaken questions stay.** Will's ruling: an earlier pick never kills a later board's idea; the question stays
  visible with an agent's one-line opinion and a "the ruling stands" answer. The general form: every decision on the
  desk carries its dependencies, and the desk shows what moved since a board was drawn.
- **Sessions, not emails.** The verified-email question is really about which session owns an upload. Unverified
  uploads bind to the session's guest row; confirmation by the same session claims them; by another session orphans
  them. Any badge or gate design that ignores this is unsafe.
- **If the control can show it, no toast.** Half of 253 toast calls announce something the control could show in
  place (Copy flips to Copied; a switch that saved itself). A toast system's first rule is subtraction.
- **A venue screen.** The album on the room's TV, filling live, with the code in the corner: the product's most
  visible moment at the party itself, and nothing draws it yet.
- **The album's afterlife.** Events have no end date and deletion is the only exit, so what an album becomes weeks
  later (a keepsake, an anniversary, a nudge to export) is a product surface with no owner.
