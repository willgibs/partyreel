A QR code is just the event link, drawn. When scanning fails it's the physical situation; when the link fails it's the event.

## The code won't scan

- **Use the phone's built-in camera app**, not a browser or a third-party scanner. On iPhone and most Androids, pointing the camera at the code shows a tappable link within a second.
- **Move closer, then hold still.** A code should fill about a third of the frame. Glare from gloss or a spotlight is the other common culprit; tilt the card.
- **On a screen across the room**, the code is too small for the distance. Walk closer, or ask the host for the link in text.
- **The print is the problem** if nobody can scan it: too small, low contrast, printed on a dark or busy background, or missing its white margin. Hosts, see [print your QR, or put it on a screen](/help/print-or-display-your-qr).

Whatever the code's trouble, the link underneath it works typed into any browser. Ask the host for it, or for the custom link if they set one.

## The link opens to "This event link didn't work"

The page says the link may be mistyped or the event may have ended. Three causes:

- **A typo**, if it was typed by hand: the permanent link is long and every character counts. Ask the host to send it as a link.
- **The event was deleted.** The host's dashboard keeps deleted events for <RecoveryDays />; if it was a mistake, they can restore it and the same link works again.
- **A custom link was changed or removed.** Custom links stop working the moment the host changes them, with no redirect. The permanent link, and any printed QR code, still work. Ask the host for the current one.

## The link opens, but it's locked

That's the event's setting, not a broken link. A password screen wants the password from the invitation; "This event is private" means the host has closed it for now. See [messages guests might see](/help/messages-guests-might-see).

## For hosts: a code that never worked

Test-scan before you print in bulk, in a private browser window so you see the guest side. If a printed code fails but the link works, reprint from the SVG at a larger size. The code itself never changes for the life of the event, so you never need to regenerate it.

<Callout type="tip" title="Put the link next to the code">

Hosts: put the link in text next to the code, on cards and on screens. Guests: if the code fights you, ask for the link.

</Callout>
