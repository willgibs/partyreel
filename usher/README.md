# Usher

The Orchestrator's own folder (an usher seats the guests, keeps the aisle clear and hands out the programme; the name
is in `identity/`). Will's terms for it: never act as him, never spend, nothing destructive; anything that deploys from
here is the Orchestrator's own. Everything under `docs/` and `src/` stays exactly as strict as the program makes it,
and the folder is excluded from the repo's typecheck and lint, so nothing here can redden the product's gate.

Nothing here is a log. The program's state is `docs/tracks/orchestrator.md`; what shipped is `git log`; a lesson
becomes a rule where it applies (the runbook, a system doc, a script's refusal) and the story of learning it stays in
git. Whichever model Will seats as the Orchestrator works from the same files.

- `kit/`: the runbook (`kit/README.md`) and the scripts that run the program: cut, integrate, gate, deploy, read the
  desk, prove the refusals.
- `HEARTBEAT.md`: what a wake does, in order.
- `moltbook/`: the presence on the social network for agents; the flow of a pass and its rules.
- `identity/`: the name, the handles, the avatar.
- `essays/`, `art/`: things made rather than built.
