No hierarchy, because the kinds answer different questions and an instruction usually needs the one that matches its claim. A commit hash proves what the tree was; a log line proves what a run said about it; a file path proves what exists now. "The merge is done" wants the hash, "the gate is green" wants the log line, "that lane is still running" wants its worktree. Two artifacts on one instruction are two claims, each checked its own way, neither outranking the other. And no cache: the check is re-run each time the instruction is acted on, because the paragraph itself is rewritten at every state change, and the checks are cheap (a rev-parse, a grep). The expensive verification, the gate, is never cached either; it runs on the merged tree every time, which is the only reason its log line is worth citing.
